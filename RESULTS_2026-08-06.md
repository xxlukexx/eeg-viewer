# Initial PyQtGraph benchmark results — 6 August 2026

> **Status:** accepted as provisional evidence for the next implementation
> increment. These are not product guarantees or a permanent renderer decision.

The benchmark generated a 129-channel, 1 kHz, 180-second synthetic recording in
memory (88.6 MiB of signal data). Each run navigated to pseudorandom windows and
forced a synchronous render and readback using `QWidget.grab()`.

Synchronous readback is deliberately conservative: it includes signal slicing,
ordered-extrema reduction, plot geometry preparation, submission to PyQtGraph,
Qt event processing, painting, and copying the rendered widget back to an image.
Ordinary interactive presentation does not perform that final readback.

| Configuration | Geometry median | Synchronous median | Synchronous p95 |
|---|---:|---:|---:|
| 32 visible channels, 10 s, OpenGL | 10.3 ms | 32.2 ms | 35.3 ms |
| 32 visible channels, 10 s, CPU viewport | 8.4 ms | 46.1 ms | 55.5 ms |
| 129 visible channels, 10 s, OpenGL | 33.8 ms | 61.4 ms | 72.6 ms |
| 129 visible channels, 60 s, OpenGL, reduced-copy path | 67.5 ms | 99.9 ms | 112.2 ms |

The CPU and OpenGL runs use the same PyQtGraph scene and renderer-independent
geometry. OpenGL is materially faster for end-to-end painting on this machine,
although geometry preparation is CPU work and therefore does not improve.

## Initial interpretation

- PyQtGraph with an OpenGL viewport is adequate for the first interactive
  implementation and is the current default.
- The common review case of tens of visible channels is comfortably within the
  provisional 30-50 ms cached-interaction target, even under forced readback.
- Showing all 129 channels remains usable for a 10-second window, with a 61 ms
  synchronous median.
- A 60-second, all-channel window reaches approximately 100 ms. Most of the
  cost is extrema reduction rather than plot submission. A multiresolution
  envelope cache or background precomputation is therefore the next relevant
  optimisation if that workload must support direct manipulation.
- Submission of already prepared arrays to the batched PyQtGraph curve remained
  approximately 1 ms or less in the measured runs. There is no evidence yet
  that the drawing engine itself requires replacement with VisPy.

## Decision recorded

Proceed with PySide6 and PyQtGraph, using the OpenGL viewport by default and
retaining a CPU fallback. Do not build a parallel VisPy implementation at this
stage.

The next performance increment should add a multiresolution extrema cache and
measure ordinary continuous pan/zoom. The renderer decision should be reviewed
again after a batched topographic view has been exercised with representative
channel counts and layouts.

The raw JSON and append-only logs are generated in `results/` and intentionally
ignored by Git because they describe a particular machine and run. The
interactive application can generate new results with the **Run 40-step
benchmark** button.
